# FinLightAI 전체 프로젝트 기획서

작성일: 2026-06-02  
문서 목적: FinLightAI 프로젝트의 서비스 방향, 핵심 가치, 사용자 경험, 기능 범위, 시스템 구조, 데이터 흐름, 개발 로드맵을 하나의 한국어 문서로 정리한다.

## 1. 프로젝트 개요

FinLightAI는 AI, 반도체, 정책, 금융 뉴스와 주식 시장 데이터를 결합해 사용자가 시장 상태와 보유 자산의 뉴스 리스크를 빠르게 이해하도록 돕는 금융 인텔리전스 대시보드다.

이 프로젝트는 투자 추천 서비스가 아니다. 사용자의 매수, 매도, 보유 판단을 직접 지시하지 않으며, 모든 결과는 참고용 시장 상태, 뉴스 신뢰도, 시장 반응, 포트폴리오 리스크 요약 정보로 제공한다.

핵심 흐름은 다음과 같다.

```text
뉴스 수집
→ 뉴스 신뢰도 검증
→ 뉴스 필터링
→ 감성 분석
→ 시장 반응 분석
→ 이벤트 점수 계산
→ RED/YELLOW/GREEN 신호 생성
→ 웹 대시보드 표시
→ Discord/Email 알림
```

## 2. 프로젝트 비전

FinLightAI의 목표는 복잡한 금융 뉴스와 시장 반응을 사용자가 빠르게 이해할 수 있는 신호 체계로 바꾸는 것이다.

뉴스는 많지만 모든 뉴스가 투자 의사결정에 의미 있는 정보는 아니다. 특히 AI, 반도체, 정책, 수출 규제, 빅테크 실적, 공급망 이슈처럼 시장에 영향을 줄 수 있는 주제는 빠르게 확산되지만 신뢰도와 맥락이 부족한 경우도 많다.

FinLightAI는 단순히 뉴스를 모아 보여주는 서비스가 아니라, 뉴스의 신뢰도와 실제 시장 반응을 함께 확인해 사용자가 현재 상황을 차분하게 파악하도록 돕는 분석 플랫폼을 지향한다.

## 3. 핵심 원칙

- 투자 추천, 매수 추천, 매도 추천, 수익 보장 표현을 사용하지 않는다.
- 단일 출처 뉴스만으로 강한 RED 신호를 만들지 않는다.
- 신뢰도가 낮은 뉴스는 분석 파이프라인에서 차단하거나 보류한다.
- 뉴스 감성만으로 신호를 만들지 않고 가격, 거래량, 변동성 데이터를 함께 반영한다.
- API 실패나 데이터 부족 상태를 숨기지 않고 사용자에게 명확히 표시한다.
- Discord 알림도 투자 지시가 아니라 시장 상태 요약과 리스크 알림으로 제한한다.
- API 키, Webhook URL, 인증 정보는 화면과 로그에 전체 값이 노출되지 않도록 마스킹한다.

## 4. 주요 사용자

FinLightAI의 핵심 사용자는 다음과 같다.

- AI, 반도체, 정책 뉴스가 주식시장에 주는 영향을 빠르게 확인하고 싶은 사용자
- 삼성전자, SK하이닉스, NVIDIA, TSMC 등 반도체 및 AI 관련 종목을 추적하는 사용자
- 여러 종목을 보유하고 있으며 뉴스 리스크와 자산 비중을 함께 보고 싶은 사용자
- 웹 대시보드보다 Discord에서 빠르게 상태를 확인하고 싶은 사용자
- 뉴스 출처와 신뢰도, 시장 반응 근거를 함께 보고 싶은 사용자

## 6. 핵심 기능

### 6-1. 뉴스 수집

뉴스 수집기는 GDELT, NewsAPI, The Guardian, Finnhub, BBC RSS 등에서 AI, 반도체, 정책, 금융 관련 뉴스를 수집한다.

주요 수집 키워드는 다음과 같다.

- AI
- 반도체
- 정책
- 수출규제
- 엔비디아
- 삼성전자
- SK하이닉스
- TSMC
- 반도체법
- 금리
- 공급망

수집된 뉴스는 원본 제목, 본문, 출처, URL, 발행일, 수집 시각, 관련 키워드, 관련 종목 후보 정보를 포함해야 한다.

### 6-2. 뉴스 신뢰도 검증

뉴스 신뢰도 검증은 FinLightAI의 핵심 품질 장치다. 신뢰할 수 없는 뉴스가 신호 생성에 사용되면 전체 서비스의 신뢰도가 떨어지므로, 분석 전에 다층 필터링을 수행한다.

검증 기준은 다음과 같다.

- 출처 신뢰도: 공신력 있는 언론사 또는 공식 기관인지 확인한다.
- 작성자 및 발행 정보: 기자명, 발행일, 원문 URL이 존재하는지 확인한다.
- 날짜 맥락: 오래된 뉴스를 최신 사건처럼 재가공했는지 확인한다.
- 제목 자극성: 과도하게 공포, 분노, 호기심을 자극하는 표현을 감지한다.
- 제목-본문 일관성: 제목과 본문 내용이 서로 맞는지 확인한다.
- 교차 보도 여부: 동일 이슈가 여러 신뢰 가능한 출처에서 보도되는지 확인한다.
- 중복 및 짧은 기사: 중복 기사, 본문 부족 기사, 키워드만 나열된 기사를 제거한다.

신뢰도 기준을 통과하지 못한 뉴스는 신호 생성에 사용하지 않는다. 단, 차단 뉴스 감사 로그에는 남겨서 사용자가 어떤 기준으로 제외되었는지 확인할 수 있게 한다.

### 6-3. 감성 분석

신뢰도 검증을 통과한 뉴스에 대해 감성 분석을 수행한다. 초기 버전에서는 규칙 기반 분석 또는 간단한 모델 기반 분석으로 시작하고, 이후 FinBERT, KoELECTRA 등 금융 및 한국어 도메인 모델로 확장한다.

감성 분석 결과는 다음과 같은 형태로 관리한다.

- 긍정 점수
- 부정 점수
- 중립 점수
- 핵심 키워드
- 관련 종목
- 분석 신뢰도

감성 점수는 단독으로 RED/YELLOW/GREEN 신호를 결정하지 않는다. 반드시 시장 반응 데이터와 함께 이벤트 점수 계산에 사용한다.

### 6-4. 시장 반응 분석

시장 반응 분석은 뉴스 이벤트가 실제 가격과 거래량에 어떤 영향을 주었는지 확인하는 단계다.

분석 지표는 다음과 같다.

- `return_1d`: 1일 수익률
- `return_5d`: 5일 수익률
- `volume_ratio`: 평소 대비 거래량 비율
- `volatility_5d`: 5일 변동성
- 가격 급등락 여부
- 거래량 급증 여부
- 동일 섹터 내 동반 움직임

뉴스가 부정적이어도 시장 반응이 크지 않다면 강한 경고를 낮출 수 있다. 반대로 신뢰도 높은 뉴스와 비정상적인 거래량 또는 변동성이 동시에 나타나면 경고 강도를 높일 수 있다.

### 6-5. 이벤트 점수와 신호 생성

이벤트 점수는 뉴스 신뢰도, 감성 점수, 시장 반응, 종목 중요도, 포트폴리오 노출도를 결합해 계산한다.

최종 신호는 다음 세 가지로 표시한다.

- `GREEN`: 특별한 위험 신호가 낮은 상태
- `YELLOW`: 주의가 필요한 뉴스 또는 시장 반응이 있는 상태
- `RED`: 신뢰도 높은 주요 뉴스와 강한 시장 반응이 함께 나타난 상태

RED/YELLOW 신호에는 반드시 주요 근거가 포함되어야 한다.

- 관련 뉴스 제목
- 뉴스 출처
- 신뢰도 점수
- 감성 분석 결과
- 수익률
- 거래량 비율
- 변동성
- 포트폴리오 노출도

### 6-6. 웹 대시보드

웹 대시보드는 사용자가 시장 상태를 가장 빠르게 파악하는 기본 화면이다.

메인 화면에서 제공할 정보는 다음과 같다.

- 오늘의 전체 시장 신호
- RED/YELLOW 종목 목록
- 주요 뉴스와 신뢰도 점수
- 차단된 뉴스 수와 주요 차단 사유
- 포트폴리오 총 평가금액
- 포트폴리오 일간 변동률
- 자산 비중 차트
- 뉴스 리스크가 큰 보유 종목

종목 상세 화면에서 제공할 정보는 다음과 같다.

- 종목별 뉴스 타임라인
- 가격 차트
- 거래량 변화
- 뉴스 신뢰도 breakdown
- 관련 뉴스 출처 목록
- 포트폴리오 내 해당 종목 비중
- 최근 신호 이력

Docs 또는 감사 로그 화면에서는 다음 정보를 제공한다.

- 저신뢰 뉴스 차단 목록
- 차단 사유
- 신뢰도 점수
- 사용된 판별 기준
- API 연동 상태
- 데이터 부족 또는 fallback 상태

### 6-7. 자산 포트폴리오 기능

MVP 단계에서는 사용자가 직접 보유 자산을 입력하는 방식으로 시작한다. 증권사 계좌 자동 연동은 보안, 인증, 개인정보 처리 정책이 준비된 이후 후순위로 검토한다.

필수 입력 항목은 다음과 같다.

- 종목 코드
- 종목명
- 보유 수량
- 평균 매입가
- 통화
- 자산 분류

계산 항목은 다음과 같다.

- 현재 평가금액
- 총 투자금
- 평가손익
- 수익률
- 전체 포트폴리오 내 비중
- 섹터별 비중
- 통화별 비중
- RED/YELLOW 뉴스 노출 비중

포트폴리오 화면은 단순한 자산 목록을 넘어, 보유 비중이 큰 종목에서 뉴스 리스크가 발생했는지 우선적으로 보여주는 역할을 한다.

### 6-8. Discord 연동

Discord는 빠른 조회와 알림 채널로 사용한다.

자동 알림 기준은 다음과 같다.

- RED 신호 발생
- YELLOW 신호 발생
- 사용자가 보유한 종목에 중요한 뉴스 리스크 발생
- API 실패 또는 데이터 수집 장애가 일정 기준 이상 지속

명령어 후보는 다음과 같다.

```text
!상태
!뉴스
!신호
!자산
!자산 삼성전자
!리스크
```

`!자산` 응답 예시는 다음과 같다.

```text
FinLightAI 자산 요약

총 평가금액: 12,450,000 KRW
일간 변동: -1.24%
평가손익: +840,000 KRW (+7.24%)

상위 보유 자산
1. 삼성전자 42.1% | YELLOW | 뉴스 신뢰도 0.88
2. NVIDIA 31.4% | GREEN | 뉴스 신뢰도 0.81
3. SK하이닉스 18.9% | YELLOW | 뉴스 신뢰도 0.84

리스크 메모
- 반도체 섹터 비중이 높습니다.
- YELLOW 신호가 발생한 보유 종목 비중이 큽니다.

안내: 이 내용은 투자 추천이 아닌 시장 상태 요약입니다.
```

## 7. 시스템 구조

현재 프로젝트 구조는 다음 역할을 기준으로 구성한다.

```text
config/                 앱 설정과 종목 universe
database/               PostgreSQL 스키마와 마이그레이션
docs/                   요구사항, 기획서, 기술 조사, 작업 계획
references/             참고 자료
scripts/                설정 및 파이프라인 실행 스크립트
src/collector/          뉴스, 주가, 신뢰도 관련 수집기
src/processor/          필터링, 감성 분석, 시장 반응, 이벤트 점수
src/signal/             RED/YELLOW/GREEN 신호 생성
src/notifier/           Discord, Email 알림
src/dashboard/          FastAPI 대시보드와 API 라우트
src/ml/                 학습, 예측, 백테스트 후보 기능
tests/                  단위 테스트
```

모듈별 책임은 다음과 같다.

| 영역 | 역할 |
|------|------|
| `collector` | 외부 뉴스와 시장 데이터를 수집한다. |
| `processor` | 뉴스 필터링, 감성 분석, 시장 반응 계산을 수행한다. |
| `signal` | 이벤트 점수를 기반으로 신호등 상태를 생성한다. |
| `notifier` | Discord, Email 등 외부 알림을 발송한다. |
| `dashboard` | 웹 화면과 API 엔드포인트를 제공한다. |
| `database` | 뉴스, 신호, 포트폴리오, 감사 로그를 저장한다. |
| `ml` | 향후 예측 모델, 백테스트, 모델 평가를 담당한다. |

## 8. 외부 연동

외부 연동은 키가 없더라도 전체 파이프라인이 중단되지 않도록 설계한다. 사용할 수 없는 provider는 비활성화하고, 화면 또는 로그에 상태를 표시한다.

| 연동 대상 | 용도 | API 키 필요 여부 | 환경변수 |
|-----------|------|------------------|----------|
| GDELT DOC 2.0 API | 글로벌 뉴스 검색 및 수집 | 불필요 | `GDELT_BASE_URL` |
| NewsAPI | 보조 뉴스 수집 | 필요 | `NEWS_API_KEY` |
| The Guardian Open Platform | 보조 뉴스 수집 | 필요 | `GUARDIAN_API_KEY` |
| Finnhub News API | 금융 및 종목 뉴스 수집 | 필요 | `FINNHUB_API_KEY` |
| BBC RSS | 공신력 보조 뉴스 수집 | 불필요 | `BBC_RSS_URL` |
| yfinance | 미국 주식 가격 데이터 | 불필요 | 없음 |
| pykrx | 한국 주식 가격 데이터 | 불필요 | 없음 |
| Discord Webhook | RED/YELLOW 알림 | 필요 | `DISCORD_WEBHOOK_URL` |
| SMTP Email | 일일 뉴스레터 | 필요 | `SMTP_HOST`, `SMTP_USERNAME`, `SMTP_PASSWORD`, `SMTP_FROM`, `ALERT_EMAIL_TO` |
| PostgreSQL | 데이터 저장 | 필요 | `DATABASE_URL` |

## 9. 데이터 저장 방향

운영 가능한 서비스가 되려면 단순 화면 출력이 아니라 분석 이력과 근거를 저장해야 한다.

저장 대상은 다음과 같다.

- 원본 뉴스
- 뉴스 신뢰도 평가 결과
- 차단 뉴스 감사 로그
- 감성 분석 결과
- 시장 반응 지표
- 이벤트 점수
- 최종 신호
- Discord/Email 알림 발송 이력
- 사용자 포트폴리오
- API 연동 상태와 실패 이력

데이터 저장소는 PostgreSQL을 기본 방향으로 한다. 초기 MVP에서는 로컬 실행과 테스트 편의성을 위해 단순한 mock 데이터 또는 경량 저장 방식을 병행할 수 있다.

## 10. 사용자 시나리오

### 시나리오 1. 오늘의 시장 상태 확인

1. 사용자가 웹 대시보드에 접속한다.
2. 전체 신호와 주요 RED/YELLOW 종목을 확인한다.
3. 각 신호의 뉴스 신뢰도, 거래량 비율, 변동성을 확인한다.
4. 필요하면 종목 상세 화면으로 이동해 관련 뉴스와 가격 반응을 본다.

### 시나리오 2. Discord에서 빠르게 자산 확인

1. 사용자가 Discord에 `!자산`을 입력한다.
2. Bot이 포트폴리오 평가금액과 일간 변동률을 계산한다.
3. 상위 보유 자산과 뉴스 리스크를 함께 보여준다.
4. 투자 추천이 아니라는 안내를 함께 출력한다.

### 시나리오 3. 저신뢰 뉴스 차단

1. 수집기가 단일 출처 또는 자극적 제목의 뉴스를 수집한다.
2. 신뢰도 검증기가 낮은 신뢰도 점수를 부여한다.
3. 해당 뉴스는 신호 생성에서 제외된다.
4. 차단 사유는 감사 로그에 남는다.

### 시나리오 4. RED/YELLOW 알림 수신

1. 신뢰도 높은 뉴스가 수집된다.
2. 관련 종목의 거래량과 변동성이 평소보다 커진다.
3. 이벤트 점수가 기준을 넘는다.
4. 시스템이 YELLOW 또는 RED 신호를 생성한다.
5. Discord로 요약 알림을 발송한다.

## 11. 단계별 개발 계획

### Phase 1. 핵심 기능 검증

- 뉴스 샘플 수집 인터페이스 구현
- 가짜 뉴스 및 저신뢰 뉴스 판별 로직 구현
- 뉴스 필터링 구현
- 규칙 기반 감성 분석 구현
- 시장 반응 계산 구현
- RED/YELLOW/GREEN 신호 생성 구현
- Discord Webhook 알림 구현 및 테스트

성공 기준:

- 낮은 신뢰도 뉴스가 신호 생성에 사용되지 않는다.
- 샘플 데이터 기준으로 신호 생성이 재현 가능하다.
- Discord 알림이 RED/YELLOW 조건에서만 발송된다.

### Phase 2. 실제 데이터 연동

- GDELT 수집기 연동
- NewsAPI 또는 Guardian 연동
- yfinance/pykrx 기반 주가 데이터 수집
- API retry, timeout, rate limit 처리
- provider별 configured, disabled, failed, fallback 상태 표시

성공 기준:

- 키가 없는 provider는 전체 파이프라인을 중단하지 않는다.
- 수집 실패 상태가 로그와 화면에 명확히 표시된다.
- 뉴스와 주가 데이터가 하나의 이벤트 분석 흐름으로 결합된다.

### Phase 3. 저장소와 감사 로그

- SQLAlchemy ORM 모델 추가
- PostgreSQL 저장 구현
- 뉴스 필터링 결과 저장
- 차단 뉴스 감사 로그 저장
- 신호 이력 저장
- 알림 발송 이력 저장

성공 기준:

- 사용자는 왜 특정 뉴스가 차단되었는지 확인할 수 있다.
- 과거 신호 이력을 조회할 수 있다.
- 데이터가 재시작 후에도 유지된다.

### Phase 4. 웹 대시보드 고도화

- FastAPI API 확장
- 메인 대시보드 개선
- 종목 상세 화면 구현
- 포트폴리오 관리 화면 구현
- Plotly.js 차트 추가
- API 연동 상태와 Docs 화면 추가

성공 기준:

- 사용자는 첫 화면에서 오늘의 위험도를 10초 안에 파악할 수 있다.
- 포트폴리오 등록부터 요약 조회까지 한 흐름으로 동작한다.
- 데이터가 없거나 API가 실패해도 화면이 깨지지 않는다.

### Phase 5. 분석 고도화와 백테스트

- FinBERT 또는 KoELECTRA 기반 감성 분석 확장
- 이벤트 점수 가중치 튜닝
- XGBoost/LightGBM 기반 방향성 예측 후보 검토
- 신호 정확도 백테스트
- 과거 이벤트 기반 성능 리포트 생성

성공 기준:

- 단순 규칙 기반보다 설명력 있는 분석 결과를 제공한다.
- 신호별 과거 성과와 오탐 사례를 확인할 수 있다.
- 모델 결과가 투자 추천처럼 보이지 않도록 표현을 제한한다.

## 12. 성공 기준

프로젝트의 성공 기준은 다음과 같다.

- 신뢰도가 낮은 뉴스가 주요 신호 생성에 사용되지 않는다.
- RED/YELLOW 신호에는 근거 데이터가 함께 제공된다.
- 뉴스 감성, 시장 반응, 포트폴리오 노출도가 함께 계산된다.
- 사용자는 웹 대시보드에서 시장 상태를 빠르게 이해할 수 있다.
- Discord에서 핵심 상태를 짧은 텍스트로 확인할 수 있다.
- API 실패, 데이터 부족, fallback 상태가 투명하게 표시된다.
- 모든 문구는 투자 추천이 아니라 정보 제공이라는 원칙을 지킨다.

## 13. MVP 우선순위

MVP에서 가장 먼저 완성해야 할 기능은 다음과 같다.

1. 뉴스 수집 및 샘플 데이터 파이프라인
2. 뉴스 신뢰도 검증 및 차단 로직
3. 시장 반응 지표 계산
4. RED/YELLOW/GREEN 신호 생성
5. 웹 대시보드 메인 화면
6. Discord Webhook 알림
7. 사용자가 직접 입력하는 포트폴리오 요약
8. 차단 뉴스 감사 로그

후순위 기능은 다음과 같다.

- Email 뉴스레터
- 증권사 계좌 자동 연동
- 고급 ML 예측 모델
- 정교한 백테스트 리포트
- 사용자별 알림 조건 세분화
- 튜토리얼 모드와 온보딩 화면
