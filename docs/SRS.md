## 1. 요구사항 개발 개요

### 1-1. 시스템 목적

본 시스템은 AI·정책·반도체 관련 뉴스가 한국 및 미국 주식 시장에 미치는 영향을 분석하여 시장 상태를 신호등(RED/YELLOW/GREEN) 형태로 시각화하는 **데이터 분석 플랫폼**입니다.

**핵심 구조**:
- 뉴스 데이터 수집 → **가짜 뉴스 판별** → 감성 분석 → 시장 반응 결합 → 신호등 생성 → 웹 대시보드 + Discord 알림

**본 시스템은 투자 추천 시스템이 아닌 시장 상태 인식 및 정보 제공 시스템입니다.**

### 1-2. 범위

| 포함 | 제외 |
|------|------|
| 뉴스 수집 및 가짜 뉴스 필터링 | 개인 투자 추천 |
| 감성 분석 (FinBERT) | 실시간 HFT 트레이딩 |
| 시장 반응 분석 | 민감 개인정보 처리 및 증권사 계좌 자동 연동 |

| 초보자용 튜토리얼 및 Docs 페이지 | |

## 3. 상세 요구사항

### 3-1. 뉴스 데이터 수집 (R01)

- **입력**: 뉴스 API 데이터 (`title`, `content`, `source`, `url`, `published_at`)
- **처리**: GDELT Global Knowledge Graph, NewsAPI 동시 수집
- **출력**: 원본 뉴스 레코드 리스트
- **조건**: 수집 키워드 = `["AI", "반도체", "정책", "수출규제", "엔비디아", "삼성전자", "반도체법"]`

#### 외부 API 키 필요 여부

| 연동 대상 | 용도 | API 키 필요 여부 | 환경변수 | 비고 |
|-----------|------|------------------|----------|------|
| GDELT DOC 2.0 API | 글로벌 뉴스 검색/수집 | 불필요 | `GDELT_BASE_URL` | MVP 1순위. 기본 URL만 설정 |
| NewsAPI | 보조 뉴스 수집 | 필요 | `NEWS_API_KEY` | 키가 없으면 해당 provider를 건너뛰고 fallback |
| The Guardian Open Platform | 보조 뉴스 수집 | 필요 | `GUARDIAN_API_KEY` | 키가 없으면 비활성화 |
| Finnhub News API | 금융/종목 뉴스 수집 | 필요 | `FINNHUB_API_KEY` | 종목 뉴스와 시장 데이터 확장에 사용 |
| BBC RSS | 공신력 보조 뉴스 수집 | 불필요 | `BBC_RSS_URL` | RSS URL 기반 수집 |
| yfinance | 미국 주식 가격 데이터 | 불필요 | 없음 | 비공식 Yahoo Finance 기반, 운영 안정성 검증 필요 |
| pykrx | 한국 주식 가격 데이터 | 불필요 | 없음 | KRX 데이터 수집 |
| Discord Webhook | RED/YELLOW 알림 발송 | 필요 | `DISCORD_WEBHOOK_URL` | 없으면 알림 발송만 비활성화 |
| SMTP Email | 일일 뉴스레터 발송 | 필요 | `SMTP_HOST`, `SMTP_USERNAME`, `SMTP_PASSWORD`, `SMTP_FROM`, `ALERT_EMAIL_TO` | Email 기능 사용 시 필요 |
| PostgreSQL | 데이터 저장 | 비밀번호/접속 문자열 필요 | `DATABASE_URL` | 로컬 기본값 사용 가능, 배포 시 별도 설정 |

**설정 원칙**:
- API 키가 없는 provider는 전체 파이프라인을 중단하지 않고 비활성화한다.
- 대시보드 설정/Docs 영역에서 각 provider의 `configured`, `disabled`, `failed`, `fallback_used` 상태를 표시한다.
- API 키와 Webhook URL은 화면과 로그에 전체 값을 노출하지 않고 마스킹한다.

### 3-2. 가짜 뉴스 판별 시스템 (R02) ⭐

**목적**: 신뢰할 수 없는 뉴스를 분석 파이프라인에서 완전 차단하여 신호 품질 보장

#### 🔍 가짜 뉴스 판별 체크리스트

**① 출처 및 작성자 확인**
- 기사명, 기자 이름, 언론사 공식 웹사이트, 발행 날짜가 정확히 있는지 확인
- 신뢰할 수 없는 매체이거나 출처가 불분명하다면 의심
- 오래된 과거 뉴스를 최신 사건인 것처럼 재편집한 것은 아닌지 날짜 확인
- **시스템 구현**: 공신력 언론 도메인 화이트리스트, 작성자 필드 존재 여부 검사

**② 자극적인 제목과 내용 경계**
- '충격!', '긴급', '경악' 등 감정(공포, 분노, 호기심)을 자극하는 단어가 많다면 주의
- 헤드라인과 본문 내용이 일치하는지 기사를 끝까지 확인
- **시스템 구현**: 클릭베이트 패턴 정규식 매칭 + 제목-본문 코사인 유사도 측정

**③ 교차 검증**
- 다른 주요 언론사나 공공기관의 공식 채널에서도 같은 내용을 다루는지 검색
- 단 하나의 매체나 개인 채널에서만 주장하는 내용은 사실이 아닐 확률이 높음
- **시스템 구현**: 동일 이벤트 커버리지 기반 교차 검증 점수 계산

**④ 맥락과 사진/영상 조작 의심**
- 문맥을 무시하고 특정 부분만 잘라내어 오해를 유발하는 콘텐츠인지 확인
- 첨부된 사진이나 영상이 AI로 조작되거나 편집된 것은 아닌지 주의
- **시스템 구현**: 본문 일관성 점수, 이미지 메타데이터 분석 (선택)

**⑤ 좋아요/댓글 수에 맹신 금지**
- SNS나 커뮤니티에서 공유수, 댓글, 좋아요가 많아도 진실이 아닐 수 있음
- **시스템 구현**: 소셜 확산 지표를 신뢰도 지표로 사용하지 않음

#### 판별 알고리즘 상세

```
최종 신뢰도 점수 = Σ(가중치 × 세부 점수)

- 출처 신뢰도 점수     × 0.30
- 날짜 정확성 점수     × 0.20
- 자극성 역점수        × 0.15
- 제목-본문 일관성     × 0.20
- 교차 검증 커버리지   × 0.15

기준: 최종 점수 ≥ 0.65 → 분석 허용
      최종 점수 < 0.65 → 분석 차단 + 의심 사유 로깅
```

#### 입출력 명세

| 항목 | 내용 |
|------|------|
| 입력 | 원본 뉴스 딕셔너리, 전체 수집 기사 리스트 |
| 출력 | `is_reliable` (bool), `final_score` (float), `flags` (list) |
| 조건 | `final_score >= 0.65` AND `source_score >= 0.8` |

### 3-3. 뉴스 필터링 (R03)

- **입력**: 가짜 뉴스 판별 통과 뉴스
- **처리**: 신뢰도 점수, 키워드 포함 여부, 중복 제거, 본문 길이 검사
- **조건**: `source_score ≥ 0.8`, `keyword_score ≥ 2`, `duplicate_flag = False`, `content_length ≥ 200`

---

### 3-4. 감성 분석 (R04)

- **입력**: 필터링된 뉴스 텍스트
- **처리**: 언어 감지 → 한국어(KoELECTRA) / 영어(FinBERT) 분기 처리
- **출력**: `sentiment_score (-1 ~ 1)`, `sentiment_label`, `confidence`

---

### 3-5. 시장 반응 분석 (R06)

- **입력**: 주가 데이터 (`close`, `volume`, `high`, `low`)
- **출력**: `return_1d`, `volume_ratio`, `volatility_5d`
- **계산식**:
  - 수익률 = `(close_t - close_t-1) / close_t-1`
  - 거래량 비율 = `volume_t / MA_volume_20d`
  - 변동성 = `rolling_std(return, 5일)`

---

### 3-6. 신호등 생성 (R08)

| 신호 | 색상 | 판단 기준 |
|------|------|----------|
| RED | 🔴 | `변동성 ≥ 임계값×2` AND `거래량 비율 ≥ 2.0` AND `감성 ≤ -0.3` |
| YELLOW | 🟡 | `수익률 절대값 ≥ 임계값` OR `거래량 비율 ≥ 2.0` |
| GREEN | 🟢 | 위 조건 미해당 (안정적 상태) |

### 3-9. API 키 및 외부 연동 상태 표시 (R15)

**목적**: 사용자가 어떤 외부 API 키를 입력해야 하는지, 현재 어떤 연동이 활성화되어 있는지 명확히 이해하도록 한다.

- **입력**: `.env` 또는 배포 환경변수에 설정된 provider별 키와 URL
- **출력**: provider별 설정 상태, 마지막 호출 시각, 마지막 오류, fallback 사용 여부
- **화면 표시**:
  - `GDELT`: 키 불필요, 기본 수집원
  - `NewsAPI`, `Guardian`, `Finnhub`: API 키 필요
  - `Discord`: Webhook URL 필요
  - `SMTP`: Email 기능 사용 시 필요
  - `yfinance`, `pykrx`, `BBC RSS`: 키 불필요
- **보안 조건**:
  - 키 원문은 화면과 로그에 표시하지 않는다.
  - 화면에는 `설정됨`, `미설정`, `실패`, `비활성`, `fallback 사용` 상태만 표시한다.
  - 오류 메시지는 provider명과 오류 유형 중심으로 기록하고 민감한 요청 URL은 마스킹한다.

### 3-10. 튜토리얼 모드 (R16)

**목적**: 처음 서비스를 사용하는 사용자가 FinLightAI의 신호, 뉴스 신뢰도, 포트폴리오 리스크, 면책 범위를 빠르게 이해하도록 돕는다.

- **진입 조건**:
  - 최초 접속 시 자동 표시
  - 마이페이지에서 `튜토리얼 다시 보기`로 재실행 가능
- **튜토리얼 단계**:
  1. FinLightAI는 투자 추천이 아니라 시장 상태 정보 제공 서비스임을 안내
  2. RED/YELLOW/GREEN 신호 의미 설명
  3. 뉴스 신뢰도 점수와 차단 뉴스 개념 설명
  4. 포트폴리오 입력 방법과 뉴스 리스크 노출도 설명
  5. Discord/Email 알림 조건 설명
  6. Docs 페이지에서 판별 기준과 감사 로그를 확인할 수 있음을 안내
- **저장 조건**:
  - 단일 사용자 MVP에서는 브라우저 `localStorage`에 완료 여부 저장
  - 사용자 계정 기능 도입 후에는 사용자 설정 DB에 저장

### 3-11. Docs 페이지 (R17)

**목적**: 차단 뉴스/저신뢰 뉴스 감사 로그가 어떻게 구분되고 해석되는지 사용자가 확인할 수 있는 문서형 페이지를 제공한다.

- **주요 콘텐츠**:
  - 가짜 뉴스 판별의 5개 점수: 출처, 날짜, 자극성, 제목-본문 일관성, 교차 검증
  - `신뢰 뉴스`, `저신뢰 뉴스`, `차단 뉴스`, `수동 검토 필요`의 구분 기준
  - 각 flag의 의미: `untrusted_source`, `date_context_mismatch`, `sensational_headline`, `headline_body_inconsistency`, `low_cross_source_coverage`
  - API 키 필요 여부와 provider별 fallback 정책
  - 투자 추천이 아니라는 면책 문구
- **구분 기준**:

| 분류 | 기준 | 처리 |
|------|------|------|
| 신뢰 뉴스 | `final_score >= 0.65` AND `source_score >= 0.8` | 감성 분석과 신호 생성에 사용 |
| 저신뢰 뉴스 | `0.45 <= final_score < 0.65` 또는 주요 flag 1~2개 | 감사 로그에 남기고 기본 분석에서는 제외 |
| 차단 뉴스 | `final_score < 0.45`, `source_score < 0.8`, 또는 치명 flag 포함 | 분석 차단, 차단 사유 기록 |
| 수동 검토 필요 | 시장 영향이 큰 키워드가 있으나 교차 검증이 부족한 경우 | 관리자/사용자 검토 대상으로 표시 |

---

### 3-12. 차단 뉴스/저신뢰 뉴스 감사 로그 (R18)

**목적**: 뉴스가 왜 통과 또는 차단되었는지 추적 가능하게 저장하고, 추후 모델 개선과 사용자 신뢰 확보에 활용한다.

- **저장 항목**:
  - 기사 ID, 제목, 출처, URL, 발행 시각
  - `final_score`, `source_score`, `date_score`, `sensationalism_score`, `consistency_score`, `coverage_score`
  - flags 목록
  - 최종 분류: `trusted`, `low_reliability`, `blocked`, `needs_review`
  - 차단/저신뢰 사유 요약
  - 생성 시각, 재검토 상태, 메모
- **화면 기능**:
  - 분류별 필터
  - flag별 필터
  - 기사 제목/출처 검색
  - 점수 breakdown 표시
  - 재검토 메모 입력
- **품질 조건**:
  - 저신뢰/차단 뉴스도 삭제하지 않고 감사 로그에 보존한다.
  - 같은 URL의 중복 저장은 방지한다.
  - 사람이 이해할 수 있는 사유 문장을 함께 저장한다.

---

### 3-13. 마이페이지 (R19)

**목적**: 사용자가 개인 설정과 자산 포트폴리오를 한 곳에서 관리하도록 한다.

- **주요 기능**:
  - 자산 포트폴리오 관리 진입
  - Discord/Email 알림 설정 상태 확인
  - 관심 종목과 키워드 설정
  - API 연동 상태 확인
  - 튜토리얼 다시 보기
  - 투자 추천이 아니라는 면책 안내 확인
- **MVP 범위**:
  - 별도 로그인 없이 단일 사용자 기준으로 동작
  - 포트폴리오 데이터는 로컬 DB에 저장
  - 증권사 계좌 자동 연동은 제외

---

### 3-14. 자산 포트폴리오 관리 (R20)

**목적**: 사용자가 직접 입력한 보유 자산을 기준으로 뉴스 리스크와 시장 신호 노출도를 확인한다.

- **입력 항목**:
  - 종목 코드
  - 종목명
  - 보유 수량
  - 평균 매입가
  - 통화
  - 자산 분류
- **계산 항목**:
  - 현재 평가금액
  - 총 투자금
  - 평가손익
  - 수익률
  - 포트폴리오 내 비중
  - 섹터/통화별 비중
  - RED/YELLOW 뉴스 리스크 노출 비중
- **화면 기능**:
  - 자산 추가/수정/삭제
  - 포트폴리오 요약 카드
  - 보유 종목별 신호 표시
  - 종목별 관련 뉴스 목록
  - CSV 내보내기/가져오기 (선택)
- **주의 조건**:
  - 매수/매도 추천 문구를 사용하지 않는다.
  - 자동 주문, 증권사 계좌 연동, 개인 투자 자문은 MVP 범위에서 제외한다.

## 4. 비기능 요구사항 (Non-Functional Requirements)

| 분류 | ID | 요구사항 | 측정 기준 |
|------|-----|---------|----------|
| 성능 | NF01 | 일일 파이프라인 처리 | 1,000건 뉴스 / 30분 이내 |
| 신뢰성 | NF02 | 가짜 뉴스 필터 정밀도 | 정밀도 ≥ 85% |
| 보안 | NF03 | API 키 보안 | .env 파일, 코드 하드코딩 금지 |
| 확장성 | NF04 | 종목 추가 용이성 | tickers.yaml 수정만으로 확장 가능 |
| 유지보수 | NF05 | 신뢰 출처 DB 갱신 | 분기별 1회 업데이트 |
| 가용성 | NF06 | 서비스 가동률 | 99% 이상 (월 기준) |
| 감사 | NF07 | 판별 결과 로깅 | 모든 가짜 뉴스 판별 결과 DB 저장 |
| 사용성 | NF08 | 최초 사용자 온보딩 | 튜토리얼 완료 후 5분 이내 주요 화면 이해 |
| 투명성 | NF09 | 차단 사유 설명 가능성 | 모든 차단/저신뢰 뉴스에 사람이 읽을 수 있는 사유 저장 |
| 보안 | NF10 | 민감 설정 마스킹 | API 키/Webhook URL/SMTP 비밀번호 원문 미노출 |

## 5. 시스템 흐름

```
튜토리얼 모드 / Docs / 마이페이지
    ↓
API 키 및 provider 설정 상태 확인
    ↓
뉴스 수집 (GDELT/NewsAPI/Guardian/Finnhub/BBC RSS)
    ↓
가짜 뉴스 판별 ← [출처 검증 + 날짜 검증 + 자극성 감지 + 교차 검증]
    ↓
[감사 로그 저장: trusted / low_reliability / blocked / needs_review]
    ↓ (신뢰도 ≥ 0.65만 통과)
뉴스 필터링 (키워드/중복/길이)
    ↓
감성 분석 (FinBERT/KoELECTRA)
    ↓
주가 데이터 결합 (yfinance/pykrx)
    ↓
이벤트 점수 계산
    ↓
신호등 생성 (RED / YELLOW / GREEN)
    ↓
[웹 대시보드 시각화] + [Docs/감사 로그] + [마이페이지/포트폴리오] + [Discord 알림] + [Email 뉴스레터]
```

## 6. 제약 및 한계

| 한계 | 보완 방향 |
|------|----------|
| 뉴스-시장 관계는 상관관계 (인과관계 미보장) | 분석 결과에 명시적 고지 |
| 가짜 뉴스 판별 100% 정확성 불가 | 이중 필터 + 사람 검토 플래그 |
| 한국어 금융 뉴스 감성 모델 품질 한계 | KoFinBERT 또는 수동 레이블링 보완 |
| 무료 API 호출 한도 | 캐싱 + 요청 최적화 |
| 공매도 데이터 무료 제공 불확실 | 선택 모듈로 분리 |
| API 키 미설정으로 일부 provider 비활성화 가능 | 키 불필요 provider 우선 사용 + 상태 표시 |
| 단일 사용자 MVP에서 계정/권한 분리 부족 | 마이페이지는 로컬/단일 사용자 기준, 추후 인증 도입 |
| 튜토리얼 과다 노출로 사용성 저하 | 최초 1회 표시 + 마이페이지에서 재실행 |

## 7. 용어 정의

| 용어 | 정의 |
|------|------|
| 신호등 시스템 | RED/YELLOW/GREEN 3단계 시장 상태 분류 체계 |
| FinBERT | 금융 도메인 특화 BERT 기반 감성 분석 모델 |
| 이벤트 점수 | 뉴스 감성과 시장 반응을 가중합한 복합 점수 |
| 가짜 뉴스 최종 점수 | 출처/날짜/자극성/일관성/교차검증 5개 항목 가중 평균 |
| 교차 검증 | 동일 사건을 2개 이상 독립 매체가 보도하는지 확인 |
| 저신뢰 뉴스 | 최종 신뢰도는 낮지만 완전한 허위로 단정하지 않고 감사 로그에 보존하는 뉴스 |
| 차단 뉴스 | 신뢰도 기준을 통과하지 못해 분석/신호 생성에서 제외된 뉴스 |
| 감사 로그 | 뉴스 판별 결과와 차단 사유를 추적하기 위해 저장하는 기록 |
| 튜토리얼 모드 | 최초 사용자를 위해 화면과 신호 해석 방법을 단계별로 안내하는 온보딩 기능 |
| 마이페이지 | 사용자 설정, 알림 상태, 자산 포트폴리오를 관리하는 개인화 화면 |
