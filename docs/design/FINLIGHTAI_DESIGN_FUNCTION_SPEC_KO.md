# FinLightAI 디자인 기능 명세서

## 2026-07-12 전시 인증 UI 결정

- 로그인 화면 주 CTA: `전시용 데모 시작하기`
- Google OAuth 코드: 구현 완료, 운영 콘솔 미연결
- Google 로그인은 운영 설정 준비 중 안내로 표시하고, 준비되지 않은 버튼처럼 노출하지 않는다.
- 전시 인증: 환경변수로 제한되는 데모 로그인
- 정식 회원가입: 전시 범위 제외
- 공개 `/signup`은 실제 회원가입 화면이 아니라 전시 데모 안내 화면으로 표현한다.

**대상**: 제품 디자이너 및 프론트엔드 개발자
**최종 업데이트**: 2026-07-12
**기준**: 작품 전시용 이메일-only MVP

## 1. 디자인 목표

사용자는 첫 화면에서 10초 안에 다음을 이해해야 한다.

1. 현재 시장 상태가 무엇인지
2. 그 판단의 뉴스와 데이터 근거가 무엇인지
3. 데이터가 실제인지, fallback인지, 연결 오류인지
4. 이 서비스가 투자 추천이 아니라는 점

화면은 운영 도구처럼 단정하고 조밀하게 구성한다. 장식보다 상태, 수치, 근거, 갱신 시각의 가독성을 우선한다.

## 2. 최신 IA

| 화면 | 핵심 목적 | 인증 |
|---|---|---|
| AI 브리핑 | 시장 상태와 근거 요약 | 선택 |
| 뉴스 가드 | 뉴스 품질과 주의 사유 확인 | 선택 |
| 산업 영향도 | 산업별 영향과 근거 확인 | 선택 |
| 포트폴리오 | 사용자 관심 자산 관리 | 필요 |
| 마이페이지 | 프로필과 개인화 상태 | 필요 |
| 설정 | 데이터/알림/표시 설정 | 필요 |
| 이메일 레터 | 기본 알림 채널 구독, 확인, 수신 거부 상태 | 필요 |
| 로그인/온보딩 | Google OAuth와 관심 설정 | 진입 |
| About/Privacy/Terms | OAuth 공개 정보 | 불필요 |

전시 버전은 이메일 알림만 보여준다. 카카오 OAuth, 카카오 알림, 카카오 채널, n8n, 챗봇 관련 메뉴와 카드는 노출하지 않는다. 로그인은 Google OAuth 코드 준비 완료 상태이며, 실제 전시 전에는 운영 origin/callback과 환경 변수 설정을 완료해야 한다.

## 3. 공통 상태 디자인

모든 API 기반 화면은 아래 상태를 가져야 한다.

| 상태 | 표시 원칙 |
|---|---|
| Loading | 기존 레이아웃 크기를 유지하는 skeleton 또는 짧은 상태 문구 |
| Success | 데이터, source, provider, 갱신 시각 표시 |
| Empty | 데이터 없음의 이유와 가능한 다음 행동 표시 |
| Fallback | 노란색 계열 label과 대체 데이터 설명 |
| Error | 오류 요약, 재시도 가능 여부, 마지막 정상 데이터 여부 표시 |
| Auth required | Google 로그인 CTA와 로그인 필요 이유 표시 |

색상만으로 상태를 전달하지 않는다. `RED`, `YELLOW`, `GREEN`, `실데이터`, `대체 데이터`, `연결 오류` 텍스트를 함께 사용한다.

## 4. 공통 헤더

- 브랜드명: FinLightAI
- 현재 화면 제목과 짧은 부제
- 데이터 갱신 시각
- 인증 상태: 사용자 nickname 또는 `Google 로그인`
- 로그인 상태에서는 logout 액션 제공
- 모바일에서는 핵심 탐색과 계정 메뉴가 겹치지 않아야 한다.

## 5. AI 브리핑

### 정보 순서

1. 시장 신호와 위험도
2. 데이터 상태/source/provider
3. AI 또는 정적 브리핑 요약
4. 근거 뉴스
5. 산업 영향 요약
6. 연결 대기 기능

### 상태 표현

- AI 요약 사용 시 `Gemini 요약` label
- Gemini 실패 시 `원문 기반 요약`과 실패/미설정 사유
- 실제 API 데이터가 없는 패널은 숫자를 채워 넣지 않고 `연결 대기`로 표시
- 신호에는 등급, 점수, 의미, 갱신 시각을 함께 표시

## 6. 뉴스 가드

### 필수 요소

- 전체/신뢰/주의/차단 segmented filter
- 수집/필터 기사 수와 평균 품질 요약
- provider 상태와 warning
- 기사 제목, 출처, provider, 게시 시각
- 신뢰도, 영향도, 감성
- 판정 사유와 원문 링크

`차단`은 허위 사실 확정이 아니라 자동 필터 결과라는 설명을 제공한다. 점수 badge는 수치와 의미 label을 함께 사용한다.

## 7. 산업 영향도

- 산업별 점수와 긍정/주의/부정/데이터 부족 상태
- 관련 뉴스 수와 관련 종목
- 선택 산업 상세 패널
- 해당 산업과 실제로 일치한 근거 뉴스

근거 뉴스가 없으면 다른 산업의 뉴스를 채우지 않는다. 빈 상태를 명확히 표시한다.

## 8. 포트폴리오

### 필수 기능

- 자산 추가, 수정, 삭제
- 자산명, symbol, 시장, 산업, 수량, 평균 매입가, 통화, 메모
- 현재가와 가격 출처
- 평가금액, 평가손익, 연결 뉴스/신호
- 로딩, 저장 중, 저장 오류, 삭제 확인

가격에는 `yfinance`, `stored reference`, `fallback` 등 출처를 표시한다. 주문 버튼이나 매수/매도 유도 CTA를 사용하지 않는다.

비로그인 사용자가 진입하면 빈 포트폴리오처럼 보이게 하지 말고 로그인 필요 상태를 보여준다.

## 9. 로그인과 온보딩

### 로그인

- `Google로 시작하기`를 주 CTA로 사용한다.
- Google OAuth 운영 설정이 끝나기 전에는 production smoke test 전 상태를 내부 작업 목록에서만 관리한다.
- Google OAuth 사용 시 요청 정보는 이메일, 표시 이름, 프로필 이미지로 제한한다.
- Google OAuth 사용 시 최소 scope(`openid`, `email`, `profile`)와 Gmail/Drive/Calendar 권한을 요청하지 않는다는 설명을 제공한다.
- 인증 오류 발생 시 재시도와 대시보드 복귀 액션

### 온보딩

- 관심 시장 복수 선택
- 관심 산업 복수 선택
- dashboard 알림 사용 여부
- 저장 완료 후 마이페이지 또는 브리핑 이동
- 저장 오류를 입력 내용 유지 상태로 표시

카카오 색상, `카카오로 계속하기`, 자체 회원가입 전체 플로우는 전시 화면에서 제거한다.

## 10. 마이페이지와 설정

### 마이페이지

- Google 프로필 정보
- 관심 시장/산업
- 관심 자산 요약
- 이메일 구독 상태와 최근 활동
- 최근 활동

### 설정

- 데이터 수집 표시 옵션
- 뉴스 가드 민감도
- 알림 설정
- 이메일 알림 설정
- API/provider 상태
- 언어/표시 설정

저장 버튼은 변경 사항이 있을 때 활성화하고, 저장 성공/실패 feedback을 제공한다.

## 11. 이메일 레터

이메일을 전시 MVP의 유일한 전달 채널로 사용한다.

### 구독 modal

- 헤더 하트 버튼으로 열며 구독 후 활성 상태와 완료 badge를 표시한다.
- 제목, 제공 내용, 이메일 입력, 수신 동의, 일일 요약/RED/YELLOW 즉시 알림 선택, 구독 CTA를 포함한다.
- 저장 중에는 중복 제출을 막고 저장 실패 문구를 입력값과 함께 유지한다.
- 구독 요청 성공 화면에는 저장된 이메일과 `확인 메일을 보냈어요` 또는 provider 미설정 시 `발송 설정 확인 필요` 상태를 표시한다.
- 확인 전에는 `확인 대기`, 확인 완료 후에는 `구독 활성`, 수신 거부 후에는 `수신 거부됨`, bounce/complaint 후에는 `발송 보류`로 표시한다.
- backdrop, 닫기 버튼, `Escape`, focus 이동 등 dialog 접근성을 제공한다.

### 연결 상태

- 포트폴리오, 마이페이지, 설정, 로그인/온보딩에서 같은 구독 상태를 사용한다.
- 미구독은 `이메일 알림 받기`, 확인 대기는 `확인 메일 확인 필요`, 구독 완료는 이메일과 `구독 활성`로 표시한다.
- localStorage는 화면 편의를 위한 보조 상태이며 서버 DB 상태를 기준으로 동기화한다.
- provider 환경 검증 전에는 `운영 발송 검증 필요`를 함께 표시한다.

### 발송 상태

- 일일 요약은 KST 기준 발송 날짜, RED/YELLOW/GREEN 수, 최신 신호 하이라이트를 표시한다.
- RED/YELLOW 즉시 알림은 사용자 설정 toggle을 제공하고 GREEN은 즉시 알림 대상이 아님을 설명한다.
- 발송 이력은 `전송됨`, `실패`, `중복 제외`, `반송`, `스팸 신고`, `지연` 등 상태 text를 제공한다.
- 수신 거부 링크는 이메일 본문에 포함된다는 안내를 개인정보/알림 설정 문맥에서 제공한다.

## 12. 공개/인증 페이지

`/about`, `/login`, `/signup`, `/privacy`, `/terms`는 서비스 목적과 데이터 사용을 이해할 수 있어야 한다. Google OAuth를 유지할 경우 OAuth 검토 기준도 충족해야 한다.

- 제품명과 실제 기능을 일관되게 표시
- 개인정보 처리와 OAuth 정보 사용 목적 명시
- 이용약관과 금지 행위 명시
- 민감 Google API scope를 사용하지 않음을 명시
- 모바일 direct URL 접근에서도 정상 표시
- 자체 회원가입, 비밀번호 찾기, 이메일 인증 기반 계정 생성 화면은 전시 범위에서 제외

새 컴포넌트를 중첩 카드로 과도하게 감싸지 않는다. 카드 radius는 기존 디자인 시스템을 따르고 반복 항목에만 사용한다.

## 14. 반응형 및 접근성

- 360px 모바일에서 가로 overflow가 없어야 한다.
- 표는 핵심 열 우선, 카드 전환 또는 가로 스크롤 정책을 명시한다.
- focus indicator를 제거하지 않는다.
- icon-only 버튼에는 `aria-label`과 tooltip을 제공한다.
- 필터, toggle, dialog는 키보드로 조작 가능해야 한다.
- 점수와 상태는 색상 외 텍스트/아이콘을 함께 제공한다.
- 긴 한국어/영문 기사 제목과 provider 이름은 wrap 처리한다.
